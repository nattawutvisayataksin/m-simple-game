## Current gameplay and technical baseline

- Choose one of five cars, then race against three AI cars.
- Drive with W/S/A/D or arrow keys; use a collected item with Q. Gamepad axes are mapped, but gamepad menu flow has not been verified.
- Collect coins and item boxes; complete Gate 0 → Gate 1 → Gate 2 → Gate 0 for each lap. The race ends after three completed laps.
- The player respawns at the start if the car falls below `y = -8`.
- Track walls use straight and curved segments on both the inner and outer edges. City roads around the track overlap at intersections to avoid visual surface gaps.
- Cars use `RigidBody3D` and Jolt. Gates and pickups use `Area3D`; the test runner exercises actual vehicle/wall contact and the ordered gate sequence.
- The race track uses 42 waypoints generated by `town.gd`. AI follows those waypoints; it does not navigate the surrounding city roads.

See [ARCHITECTURE.md](ARCHITECTURE.md) for node/script responsibilities, physics layers, and test coverage; [GDD.md](GDD.md) for game scope and history; [ART_DIRECTION.md](ART_DIRECTION.md) for scene/readability constraints; and [ASSETS.md](ASSETS.md) for asset provenance and license notes.

## Regression test

Run from the repository root. On a fresh checkout, import the project first:

```powershell
$godot = (Get-Command godot -ErrorAction Stop).Source # or set the installed Godot 4.7.2 executable path
$project = "games/game3_car"
& $godot --headless --path $project --import
if ($LASTEXITCODE -ne 0) { throw "Godot import failed" }
& $godot --headless --path $project --scene res://tests/test_game3_runner.tscn
if ($LASTEXITCODE -ne 0) { throw "Game 3 regression tests failed" }
```

The runner is `tests/test_game3_runner.tscn` with assertions in `tests/test_game3.gd`. The last recorded result is **53 PASS / 0 FAIL**. Godot reported outstanding ObjectDB/resource references during runner teardown despite exit code 0; this is a cleanup note, not a failed assertion.

## Manual playtest still needed

Before calling this build playtested, run a race with a human player and verify:

1. The car can complete three laps by following the road, and a missed checkpoint does not count as a lap.
2. The car cannot shortcut around the track in a way that bypasses the ordered gates.
3. Vehicle-to-vehicle and vehicle-to-wall collisions feel reasonable in the GUI, including all four corners.
4. The red/cream barriers follow the curves without crossing the drivable lane; outer-city roads look connected at intersections.
5. From the chase camera, the next gate, road edges, coins, and item boxes are readable and do not look like misleading obstacles.
6. Item use, respawn, race finish, and restart work in a normal GUI session.

The automated physics tests are not a substitute for these visual and hands-on checks. Record any user-reported issue, reproduce it, and make focused changes; do not add assets or change the art direction without direction.
